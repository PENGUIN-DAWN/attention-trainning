# 维护与交接

## 文档各自负责什么

| 信息 | 优先维护的位置 |
| --- | --- |
| 产品对象、目的和边界 | [PRODUCT.md](PRODUCT.md) |
| 当前训练身份、引擎和功能入口 | [trainings.json](../../android-app/config/trainings.json) 为事实源，[TRAININGS.md](TRAININGS.md) 为阅读入口 |
| 发布版本、包名、最低系统 | [AndroidManifest.xml](../../android-app/AndroidManifest.xml) 为事实源；同步项目首页和知识库快照 |
| 架构、构建、测试与数据协议 | `docs/` 原有四份技术文档；知识库用链接引用 |
| 重要决定和被取代的历史约定 | [DECISIONS.md](DECISIONS.md) |
| 实际验收结果 | 对应版本的 `安卓手机版/验证记录-版本.md`、原始报告和凭据；知识库说明证据范围 |
| 尚未决定或执行的事项 | [BACKLOG.md](BACKLOG.md)，不能写入已完成结果 |
| 原视频、研究与改编依据 | `训练工具开发/`；标明原任务、App 改编和证据限制 |

## 什么变化需要同步

1. **新增或改名训练**：先核对 ID/key 不被复用，改注册表与实现，再更新训练目录；规则变化记录规则版本和比较方式。
2. **修改存储/备份**：更新实现、`DATA-AND-SIGNING.md` 和相应决定；验证旧备份、无效导入、失败回滚与重试。
3. **修改架构/工程入口**：更新 `ARCHITECTURE.md` / `BUILD.md` / `TESTING.md`，修正知识库中的链接，标明旧脚本的历史身份。
4. **发布版本**：从 Manifest 取版本，不自行猜版本；完成规定验证后更新首页、版本资料、知识库基线与证据页。保留旧 APK。
5. **用户确认新方向**：记录确认日期及准确含义；把对应待确认项更新为已确认，不把未答问题推定为同意。
6. **获得真实使用反馈**：注明反馈来源和环境，不把几个人的感受写成普遍效果证据。

知识库中的“当前”均对应注明的核对基线。版本升级后如果尚未复核，应明确保留旧基线，避免只改版本号造成误导。

## 给下一位开发者或 AI 的交接文本

```text
先读 AGENTS.md 和 docs/knowledge-base/README.md。
这是供作者自己及身边几位朋友使用的安卓离线注意力练习工具。
版本以 AndroidManifest.xml 为准，训练身份以 config/trainings.json 为准。
先核对 git status，保留用户已有改动，再按任务读取实际代码和原始技术文档。
区分最新用户决定、当前实现、历史材料、建议和验证结果。
保留已有训练/数据/备份兼容/包名/签名/WebView 来源与离线能力。
不要直接编辑生成页面，不用旧归档脚本代替统一工程入口。
按改动范围验证；报告本次实际执行与仍未验证的内容，并同步相关文档。
```

## 完成一次知识库更新前

- 链接能定位到实际文件，当前名称和稳定编号与注册表一致。
- 每项事实能找到源码、用户确认或报告依据；没有补写用户背景、研究结论或训练效果。
- 建议和未验证项没有混入已确认/已完成内容；引用旧材料保留版本背景。
- 没有加入个人成绩、签名私钥、凭据或设备敏感标识。
- 用 `git diff --check` 和 `git diff` 检查格式与范围；纯文档更新不必重建 APK。

这套知识库存放在项目中，不写入全局个人记忆，也不替代源码和验收报告。
