# 1.62 第七项入场与立体效果

2026-10-22，作者要求十球档运动改为 10 秒，增加立体高光、小球逐颗入场与出现音效，随后以发光确认目标，并提供 `SVID_20261022_115346_1.mp4`。作者随后明确：**只借鉴效果，不改变小球和背景颜色**。最终实现遵照这个最新要求，不使用参考视频的金球或深色背景。

## 参考与最终范围

参考录屏约 9.65 秒，能看到倒数、逐颗出现、目标光圈和“记住它们”；片段结束时仍在目标确认，没有展示正式运动段。录屏约 26.86fps 是该视频文件信息，不能当作 App 或手机刷新率证据。本次只借鉴视觉顺序；出现音效为自己离线合成的轻柔短音，没有直接使用录屏音乐。

最终保留 1.61 的蓝色球 `#485f80`、棕金目标 `#a46124`、目标光圈色 `#f3ca7e`、背景 `#f3f5fa`、方形场地、球径和初始排列。通过固定在球面的渐变高光与内阴影增加立体感；运动期间不保留目标光圈，也不制作拖尾或逐帧模糊。首页和其他训练外观保留。

## 阶段和规则 v3

1. 倒数 2、1，各 800ms。
2. 每 160ms 按随机顺序显示一个小球，弹出动画 280ms，最后留 180ms 稳定时间；十球入场共 1900ms，十二球共 2220ms。
3. 所有球完全显示后，目标发光确认完整 2500ms。音效只作准备提示，不编码目标身份。
4. 发光停止，所有球恢复相同蓝色、高光和明暗样式，再开始正式运动：**十球 10000ms**，十二球仍 8000ms；速度仍 0.24 / 0.27，目标数仍 4 / 5，每轮仍 3 题。
5. 运动停止后才显示编号和启用作答。入场、目标确认、运动不计作答用时。

新条件包括入场参数、球面样式和场地比例（保留为 1），故升为规则 v3。v1 的原速度/原时长、v2 的提速/原时长继续按原参数校验，不能把旧记录改写为 v3。三种规则与两个预设形成六个比较组。备份仍为 v4，导入仍兼容 v1–v4。

`tool-rules.js` 管条件、生成、碰撞和校验；`tool-ui.js` 管可取消阶段；`tool-motion.js/css` 管缓存球面、入场和目标光圈；`tool-audio.js` 在点击开始/下一题的用户手势中开启 Web Audio，实时合成短音，无外部音频文件或联网请求。

## 声音与取消

第七项设置新增“入场音效：开启 / 静音”，默认开启，保存在原设置存储键；旧设置缺失该字段时使用默认值，不修改其他项目设置。关闭音效不会创建 AudioContext。音效不可用时显示提示并继续视觉训练。

后续公共反馈接入将该设置显示名称改为“装饰音效”，保留原 `sound` 字段与默认值，并与全局装饰开关共同生效。`tool-audio.js` 现在是公共 `FocusFeedback` 的薄适配，原短音参数与阶段触发不变；新增作答点击反馈不占用观察/运动时长。差异通过 `feedback-baseline.json` 追加绑定，原 1.62 契约不改。接口与本次验证见 [统一音效与动效接入](FEEDBACK.md)。

返回、切后台、隐藏页面时取消待执行帧、弹出动画、目标脉动和已排程音频，并中断本轮。准备/运动中遇到超过 250ms 的停顿仍中断，避免跳过不可见运动或成批补播。减少动画时保留顺序和准备时长，只逐颗显示、不弹跳；目标为静态光圈，正式追踪运动仍保留。

## 契约与验证

`motion-baseline-162.json` 链接原样保留的 1.61 契约，明确记录本轮四份变更源码的前后哈希及新增音效文件；旧 1.50/1.61 快照不改。配置中第七项标为可选有声项目，原第十五项数字音频未变。
